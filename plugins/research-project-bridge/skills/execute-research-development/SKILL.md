# Execute Research Development

Treat the research work item, acceptance criteria, governed Wiki evidence, and
repository state as the execution contract.

## Start

1. Call `research_get_work` for the selected item.
2. Read only the surrounding project context needed for execution.
3. Use `wiki_navigate` for architecture, requirements, prior decisions, known
   issues, and validation obligations; use `evidence_read` for critical claims.
4. Confirm the workspace and base ref. Stop on ambiguity.
5. Claim a provided execution with the current thread ID and a stable
   idempotency key.

## Execute and validate

- Preserve unrelated user changes.
- Satisfy the full acceptance criteria, not merely a demonstration path.
- Run proportionate unit, integration, security, performance, and product-flow
  validation.
- Record failures, unavailable providers, negative quality results, and material
  exclusions exactly.
- Treat Wiki source references as navigation aids until raw evidence is verified.

## Report

Use `execution_report` at meaningful milestones and completion. Include status,
summary, changed paths, validation outcomes, artifact paths, and a stable
idempotency key. Request independent review when ready; never mark critical work
complete or approve evidence generated by this execution.
