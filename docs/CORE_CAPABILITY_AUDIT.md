# 核心业务能力审计

审计日期：2026-07-24

本报告只检查可执行的数据链路、持久化事实和可复现测试，不以页面存在、按钮可点击或
接口返回 200 作为“已实现”的判据。

## 结论

系统并非只有界面：代码摄取、Codex 会话解析、实验/文档结构化、关系复核、版本漂移和
评测均已有真实数据模型与持久化实现。但本轮审计也确认了八个会直接损害科研判断的
问题：

1. 旧向量相似度把正交向量映射为 0.5，导致无关证据获得虚假基础分。
2. 结构化来源只使用自然语言问题中的一个最长片段，长问题和中文问题经常召回为空。
3. 跨源融合后只保留“两个端点都入选”的边，真实 Claim→Run、Codex→Code 关系会丢失。
4. 无 LLM 时的问题分析只返回来源计数，没有输出证据事实、反证、版本和缺口。
5. Git 摄取没有尊重 `.gitignore`，且 Import 后备匹配为 O(文件×Import)；大型本地项目
   会把生成数据纳入索引并在结构阶段明显变慢。
6. Git 文件发现先解析符号链接再检查链接类型，可能把链接和目标发布成相同稳定 ID。
7. 部分克隆缺少旧 Git 对象时，历史 Diff 同步会阻塞并使当前代码索引整体失败。
8. 问题明确要求实验或文档证据时，只召回代码和会话仍可能被错误判定为完整支持。

上述问题已在本轮修复，并增加回归测试。

## 本轮关键修复

### 向量与检索

- 将当前模型标识升级为 `local-hash-v2`。
- 正交向量相似度从错误的 0.5 修正为 0；负相关按 0 处理。
- dense 通道只接受大于 0.05 的正向相关结果。
- 按每条已存向量的 `embedding_model` 生成对应查询向量，旧 v1 索引无需立即重建。
- 去除 20,000 条 dense candidate 的静默上限；当前 Scope 内向量全部参与计算。
- Trace 使用真实算法名 `weighted-hybrid-v2`，不再错误标成 RRF。

### 多源检索与证据路径

- 英文标识、数字和中文 n-gram 共同参与结构化来源检索，不再只查整句最长词。
- ExperimentRun 检索文本包含 config、dataset ID 和 dataset version。
- 同一实体的多个 Search View 在跨源融合前去重，合并命中通道。
- 结果按来源保留至少一个相关入口，再按全局相关性补齐。
- 保留从命中证据出发的一跳确认关系，并把未直接命中但被关系连接的实体作为
  `related_entities` 放入 Evidence Pack 和 Citation Map。
- ACL 在关系扩展前再次检查两个端点，避免通过关系侧漏未授权实体。

### 问题分析

- 角色判断基于实际实体类型、版本和关系；不再因为出现任意 Code 结果就同时声称
  “当前代码”和“历史代码”均已满足。
- 无 LLM 模式返回判定、置信度、主要证据、反证、适用版本、缺失角色、来源覆盖和
  关系路径，并只列出实际引用的 Citation ID。
- 用户在问题中明确点名代码、Codex、实验、文档或工作区来源时，每一类都会进入动态
  证据完备性检查；未召回的来源明确进入 `missing_evidence`，不能用其他来源替代。
- 删除未被运行时引用的旧 `AnswerService`，避免两套问答逻辑继续分叉。

### 摄取与静态关系

- Git 仓库使用 `git ls-files --cached --others --exclude-standard` 发现文件，真实遵守
  `.gitignore`，避免把本地数据库、缓存和生成目录错误向量化。
- 符号链接在解析真实路径前排除，规范化后的仓库相对路径再次去重，避免稳定 ID 冲突。
- 当前代码摄取不再隐式拉取远程历史；部分克隆缺失对象时发布代码、Symbol、向量和
  关系，并把历史状态记录为 `partial`，由独立历史同步动作重试。
- Import 后备解析建立路径后缀索引，移除 O(文件×Import) 全表扫描。
- CALLS 关系只在同文件唯一目标或已存在 IMPORTS 文件关系时跨文件连接，避免把
  `dict.get()` 等常见方法错误绑定到项目中唯一名为 `get` 的业务方法。
- Codex 相对路径候选优先绑定 cwd 所属仓库；绝对路径只能绑定其真实所在仓库，避免
  多仓库同名文件产生伪关系。

## 可复现验收

本轮使用三层验收：

1. 完整自动化测试：66 项测试覆盖摄取、检索、Codex、绑定、实验、文档、工作区、
   版本历史、ACL、MCP、有效性分析和 Web 交互契约。
2. 对项目自身做隔离的真实 Git 摄取：
   - 发现 157 个源码/测试/前端文件；
   - 发布 154 个文件、1,278 个 Symbol、1,432 个 v2 向量视图；
   - 生成 3,505 条结构关系；
   - 同步 9 个 Commit 和 500 个 DiffHunk；
   - 0 个解析错误；
   - 完整发布耗时约 8.2 秒。

隔离验收数据库位于 `/private/tmp/evidence-rag-core-audit-4`，不修改项目的正式数据。

3. 对正式数据库执行原子重建并核对 Active Generation：
   - Codex 仓库：4,273 个文件、52,279 个 Symbol、56,552 个 v2 向量视图、
     97,722 条保守结构关系、500 个 Commit、500 个 DiffHunk；
   - code-graph 仓库：126 个文件、524 个 Symbol、650 个 v2 向量视图、
     1,026 条结构关系；缺失的历史对象记录为 1 个可重试历史错误；
   - Codex 会话：2 个会话、21 个 Turn、3,547 个 v2 证据视图、5,021 条会话关系；
   - 真实全源问题在约 6.1 秒内返回两个新索引代和 160 条关系路径；只存在代码与
     Codex 证据时，判定为 `insufficient_evidence`，并明确列出缺少实验和文档证据。

## 仍需持续治理

- 当单项目向量规模达到数十万以上时，应加入可替换的 ANN 后端；在此之前系统选择
  “全量正确扫描”而不是静默截断。
- 静态 CALLS/IMPORTS 是保守关系：宁可 unresolved，也不以同名猜测伪造关系。
- PR Review、CI Webhook 和 SCIP 在适配器、持久化、权限和回归测试全部存在前，保持
  “未实现”状态，不做占位式完成。
- 线上项目应建立自己的 Golden Question、禁止实体和必需证据路径，持续执行回归，
  不能只依赖通用单元测试。
