# RAG 全产品启动与交互自测报告（2026-08-02）

## 1. 结论

本次在隔离数据目录中真实启动项目，并完成后端、前端、API、桌面端、移动端和主要业务交互的联合自测。

- 仓库内 L0–L3 工程链路可启动、可测试、可浏览，主要交互未发现 P0/P1 功能阻塞。
- Code 仓库摄取和 Codex 会话摄取均完成，页面能展示真实仓库、会话和关系图数据。
- 前端 28 个测试文件、145 个测试，后端安全全量 1863 项，静态检查与内存编译均通过。
- 可信查询的规划、治理、证据状态和安全拒答可用，但真实 Code/Codex 查询出现约 3.1 秒源级超时，回答结果为诚实 `REFUSAL`。
- 因此当前准确状态仍是 `DEFAULT_V1 / QUALITY_HOLD / NO_RELEASE`。工程完整不等于生产质量达标。
- L4/L5 的正式库迁移、生产 shadow/canary、远程模型与默认 V2 切换仍属于外部授权或生产证据阶段。

新版页面能显示完整待处理总数、前 500 条高置信候选、源/目标证据对照，并新增：

- “扫描候选”：从已经摄取的 Code/Codex 数据生成或刷新关系；
- “全部通过”：服务端处理完整待复核快照，而不是只处理前端展示的 500 条；
- 逻辑去重：多个候选指向同一源/目标/证据时只创建一条关系，同时保留全部候选 ID 与路径；
- 二次确认：明确显示将处理的总数；

- 服务端 reviewer 和逐关系 audit，不接受浏览器自报审阅主体。

本次只打开并验证了“确认全部 17,951 条”的弹窗，随后取消，没有替用户实际批量通过关系。错误 `expected_pending=1` 的 API 对抗请求返回 409，前后统计均保持 17,951，证明没有部分写入。

另在该隔离库的临时副本上实际执行完整批量事务：17,951 条候选全部转为 confirmed，生成 11,398 条去重逻辑关系和 1 条批次审计，剩余 pending 为 0；验证完成后删除副本。正在展示的隔离库仍保持 17,951 条待复核、0 条已确认。

## 6. 问题与分级

| 级别 | 问题 | 影响 | 建议 |
| --- | --- | --- | --- |
| P1 质量 | governed Code/Codex 查询约 3.1 秒源级超时 | 智能回答拒答，不能发布为默认 V2 | 优化候选生成、预算分配和索引热启动；以真实回放重新评估 |
| P2 性能 | 大会话详情约 4 MB，首屏约 5–6.5 秒 | 大会话浏览偏慢 | 服务端分页/窗口化、前端虚拟列表、增量详情加载 |
| P2 体验 | 会话节点拖拽手柄命中区域较小 | 用户可能误以为不能拖拽 | 扩大手柄热区并加入 hover/按下反馈 |
| P2 体验 | 390 px 总览研究问题卡片被压成单字窄列 | 移动端首屏可读性差 | 卡片改为纵向布局，移动端隐藏非必要说明并重新分配按钮位置 |
| P2 性能 | 首次全量关系扫描约 3 分钟 | 复核候选首次生成等待较长 | 改为异步工作流、增量扫描，并在页面显示可恢复进度 |
| P2 工程 | 前端构建与后端静态指纹测试共享输出目录 | 并行运行时会产生瞬态失败 | CI 中串行化构建与静态指纹回归，或使用隔离构建目录 |
| P3 维护 | Starlette TestClient 弃用提示 | 未来依赖升级风险 | 规划迁移到显式 transport |

本轮未发现会导致数据越权、错误发布、静默伪答案或正式库破坏的 P0 问题。
