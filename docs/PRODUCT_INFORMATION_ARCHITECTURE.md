# 多源研发证据 RAG 产品信息架构

本文把《多源研发证据RAG系统_项目设计文档_v1.0》和 `rag_ui_v2` 的
20 个页面映射到当前可运行平台。它约束导航、页面职责和跨页面交互，避免再把
技术存储对象直接暴露成业务页面。

## 1. 产品主线

平台的主对象不是“知识库”或“数据源”，而是一个可验证的科研问题：

```text
Research Topic / Iteration
  → Question
  → Evidence Pack
  → Code / Codex / Experiment / Document evidence
  → Claim validity / conflict / missing evidence
```

用户主流程：

```text
提出问题
→ 默认检索整个项目（必要时再缩小仓库、版本或来源范围）
→ 查看回答与证据角色
→ 在同一工作台核对代码
→ 跳转到 Run、文档或会话原始位置
→ 复核推断关系或发起复验
```

## 2. 一级导航

| 分组 | 页面 | 职责 |
|---|---|---|
| 科研协同 | 项目工作台 | 研究主题、迭代、证据健康和待办 |
| 科研协同 | 证据工作台 | 顶部项目提问；左侧项目来源（代码、会话、实验、科研文档）；右侧回答、证据、关系 |
| 研发资产 | 代码与版本 | 仓库接入、Generation、Git 历史、文件和 Symbol |
| 研发资产 | 研发会话 | Codex Thread、Turn、命令、Patch、Episode 和会话对照 |
| 研发资产 | 实验与数据 | Experiment、Run、Metric、Dataset、Config、Artifact、Notebook |
| 研发资产 | 科研文档 | DocumentVersion、Section、Table、Figure、Claim 和原文定位 |
| 证据治理 | 关系复核 | 跨源候选关系的解释、确认和拒绝 |
| 证据治理 | 有效性分析 | Claim、原始 Run/Commit 与当前版本的漂移和复验状态 |
| 平台控制 | 治理与运维 | Golden Questions、Trace、审计、策略和来源运行状态 |

不再把以下技术对象作为一级业务页面：

- `Raw Object Ledger`
- `Source Event`
- 单独的“实验数据接入”
- 脱离科研对象的“原文与数据源”

它们分别下沉到治理运维、实验与数据、科研文档的上下文操作中。

## 3. 证据工作台

证据工作台是系统默认调查界面，采用三层结构：

1. **顶部对话区**：直接提问并展示整个项目的索引覆盖；仓库、意图和来源范围
   收进可选的“筛选范围”，不能成为使用前置条件。
2. **左侧项目来源区**：可在代码、研发会话、实验和科研文档之间切换；代码以
   `Repository → Directory → File` 层级树展示，并使用浅色连续源码阅读区显示
   分支、Commit、行号和命中位置。
3. **右侧 RAG 区**：用回答摘要、证据来源、关系链和知识图谱四层组织
   Primary/Supporting/Counter/Missing Evidence、
   Citation、关系与来源回跳。

回答摘要必须先展示“原始问题 → 系统理解 → 查询范围 → 回答模式”，再给出结论。
检索摘要不能伪装成生成式回答；未启用生成模型时要明确标记为“基于证据直接回答”，
并把最相关的原文片段放在结论旁边。

知识图谱覆盖三个真实证据域：

- **代码图谱**：Commit、FileVersion、DiffHunk、CodeSymbol、CALLS/DEFINES 等关系。
- **Codex 会话图谱**：Thread、Turn、Goal、Command、Tool、Patch、Validation 等关系。
- **文档图谱**：Document、Section、Table、Figure、Claim 及其确定性关系。

每个图谱提供“关系网络”和“向量语义邻域”两种模式。关系网络只展示来源中的真实
关系；语义邻域用虚线 `SEMANTIC_MATCH` 连接查询向量与召回实体，来源中的确定性
关系仍使用实线，二者不能混为一谈。大规模图谱默认展示稳定抽样子图，并分别标注
项目总量与当前可见量；用户可在 24、36、60 个可见节点间切换，不能把浏览器当前
可交互子图冒充为全量索引。节点检查器必须显示稳定 URI、版本、原始定位器和直接关系，
并支持回跳代码、会话或科研文档。没有已摄取文档时，文档图谱保持真实空态。

图谱画布的操作骨架参考 `FalkorDB/code-graph`：全画布力导向节点、浮动搜索、
实体类型开关、节点右键菜单、相邻节点聚焦、两点路径、隐藏/恢复、缩放、居中和
导出。平台在此基础上增加代码/Codex/科研文档三域切换、关系/语义模式区分、
稳定证据定位器和来源回跳；不能退化为只读矩形流程图，也不直接照搬上游的单仓库模型。

左右区之间使用可拖拽分隔条，并提供 `40/60`、`50/50`、`60/40` 和单侧聚焦。
比例在浏览器本地保存。默认查询 Scope 是整个项目；RAG 中选中证据时，左侧必须
自动切换到相同来源；代码证据还需展开并定位到同一 Repository、Commit、File
和行号。在代码仓库页切换仓库时，证据工作台 Scope 仍保持全项目查询，但会展开
对应仓库作为浏览上下文。

## 4. 科研资产语义

### 实验与数据

“数据”指实验事实链中的 DatasetVersion、配置、参数、Metric、Artifact 和
Notebook 执行，不是任意上传文件。MLflow、Notebook 和手工 Run 都是实验中心的
上下文入口。

### 科研文档

“原文”指 DocumentVersion 中可定位的 Page、Section、TableCell、Figure 和
Claim 原始位置。文档列表、结构化内容和 Claim 验证应并列展示。

### 技术来源台账

Raw Object、事件、解析器和 Generation 是平台运维信息，只在治理与运维中用于
故障调查、重建和审计，不与科研业务对象并列。

## 6. 交互一致性规则

- 任何 Repository 选择都写入同一个前端 Scope 状态。
- 任意 Evidence Card 均提供“在当前工作台核对”或“在来源中打开”。
- 空态说明下一步动作，不展示与业务无关的技术术语。
- 失败状态保留错误原因和重试入口；成功状态显示发布的 Generation/Version。
- 模态框只负责短创建任务；浏览、比较和复核使用完整工作台。
- 所有跨页面跳转保留当前项目、仓库、问题和已选实体。
- 原始证据始终显示稳定 URI、版本、时间和 ACL，不以摘要代替来源。
